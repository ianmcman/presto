In data/mod.rs:

- `fn usable(s: &CoreState) -> bool { s.engine == EngineStatus::Ready && s.auth == Some(AuthState::SignedIn) }` and `fn signed_out_transition(prev: &CoreState, cur: &CoreState) -> bool` implementing the wipe rule from the interfaces block (unit test both with constructed states, including: None -> SignedOut false; SignedIn -> Expired false; SignedIn -> SignedOut with restarts 0 -> 1 false; SignedIn -> SignedOut same restarts true).
- In `DataHandle::new`, `rt.spawn` a watcher holding a `Weak<Inner>` (exit when the handle is dropped) over `client.core().state()`. Initialize `prev` from the current state at spawn time (`borrow().clone()`), so a handle created while already usable triggers nothing; 04-07 tests rely on this. On each change, before anything else, collapse coalesced updates by comparing against `prev` only:
  - `signed_out_transition(prev, cur)` -> `wipe(reload: false)`.
  - `!usable(prev) && usable(cur)` (engine ready or auth restored, D-04) -> `refresh_storefront()`; on Ok(sf) `store.set_meta("storefront", sf)` (spawn_blocking); if sf differs from the previous cached storefront, reset every slot to `ListState::default()` with gen bumped (other account key). Then `invalidated_at_ms = now_ms()` so every other open slot is stale on next open, and `refresh(focused)` if a view is focused. Only the focused view is revalidated (Pitfall 7).
- `fn wipe(&self, reload: bool)`: in spawn_blocking `store.wipe()` and `art.clear()`; `client.set_storefront(None)`; for every slot bump gen and publish `ListState::default()` (error None); if `reload` and a view is focused, `refresh(focused)`.
- `pub fn clear_cache(&self)` = `wipe(reload: true)`. Clear cache keeps sign-in; the next fetch re-reads the storefront.

Create tests/data_wipe.rs with one `#[tokio::test(flavor = "multi_thread")]` per behavior bullet, sharing a tempdir `Paths::under(dir.join("data"))` across runs where needed.
