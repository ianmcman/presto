Decisions made here (research open questions):
- Frame types live in `presto-ipc` (module `ctl`) with their own schema test, because `tests/schema.rs` only walks `Frame`.
- `Status.volume` is an integer percent 0..=100. `Status.engine` has four values: `ready`, `starting`, `restarting`, `failed` (Drift and Failed both map to `failed`; extends D-14, consumers treat unknown as not-ready).
- `shuffle` with no arg toggles; `repeat` with no arg cycles; both resolved server-side (`on: None` / `mode: None`).
- `--demo` is a clap `global = true` flag so `presto --demo status` targets the demo sockets.
- Exit codes: 0 ok, 1 not running, 2 usage, 3 rejected.

```rust
pub const CTL_PROTO: u32 = 1;
pub const MAX_LINE: usize = 4096;
pub struct CtlRequest { pub proto: u32, pub id: u64, #[serde(flatten)] pub op: CtlOp }
#[serde(tag = "op", rename_all = "snake_case")]
pub enum CtlOp {
  Play, Pause, Toggle, Next, Prev, Stop,
  Seek { ms: u64 }, SeekBy { ms: i64 },
  Volume { pct: u8 }, VolumeBy { pct: i32 },
  Shuffle { on: Option<bool> }, Repeat { mode: Option<RepeatMode> },
  Status, Subscribe, Raise, Quit,
}
pub struct CtlReply { pub proto: u32, pub id: u64, pub ok: bool,
  #[serde(default, skip_serializing_if = "Option::is_none")] pub error: Option<String>,
  #[serde(default, skip_serializing_if = "Option::is_none")] pub status: Option<Status> }
pub struct Status { pub proto: u32, pub state: StatusState, pub position_ms: u64, pub duration_ms: u64,
  pub volume: u8, pub shuffle: bool, pub repeat: RepeatMode, pub track: Option<StatusTrack>,
  pub auth: Option<AuthState>, pub engine: EngineLabel }
pub struct StatusTrack { pub id: String, pub title: String, pub artist: String, pub album: String, pub artwork_path: Option<String> }
pub enum StatusState { Playing, Paused, Stopped, Loading }
pub enum EngineLabel { Ready, Starting, Restarting, Failed }
```
